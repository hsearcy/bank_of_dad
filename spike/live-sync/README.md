# Local synthetic live-sync spike — NEVER DEPLOY

This is a disposable development fixture, **not an authentication or hosting implementation**. It deliberately exposes privileged family bootstrap, grant creation/revocation, expiry and fault injection through a loopback-only test worker; it puts fake grant tokens in WebSocket URLs. It is unsafe on a network and must never receive real identities, credentials, or data. It does not use a live application, existing database, OIDC, or the global revocation spike.

The temporary JS Worker serves a purpose-built test page, **not the real `static/app.js` UI**, and forwards to a real Python `FamilyBank` Durable Object subclass. Nothing wires this fixture into the real app. It uses the existing `FamilyAuthorization` and real banking functions/SQLite adapter. Each synthetic family has its own DO/database. The Python DO accepts an **ordinary** (not hibernating) WebSocket only after an authorized family read; before each broadcast it rechecks every connection's current grant, closing denied ones. The fixture routes the seven supported bank mutations through one post-commit invalidation path; false business results, exceptions, conflicting payloads and idempotent replays do not broadcast. The fixture's pre-check and mutation are synchronous without an intervening await within one DO event. The DO-local authorization still governs reads and writes. Bootstrap creates one synthetic child with the domain's actual starting balance and issues two synthetic grants. A separate test-only operation adjusts the allowance clock to exercise a positive reward.

## Run

Prerequisites: Node, Python, Chromium, and the pinned Wrangler from `tests_hosted/package-lock.json`. The browser test also requires Playwright. For example, from repository root:

```sh
npm ci --prefix tests_hosted
npm install --no-save --package-lock=false --prefix tests_hosted playwright@1.64.1
PLAYWRIGHT_MODULE="$PWD/tests_hosted/node_modules/playwright" python spike/live-sync/test_browser.py
```

Override `WRANGLER_BIN`, `PLAYWRIGHT_MODULE`, or `CHROMIUM` if installed elsewhere. `TMPDIR` controls the disposable parent directory. The harness copies source to a new temporary directory, uses separate Wrangler HOME/cache and persistent state, picks a loopback port, stops its own process group, and deletes the state on exit. Do not point it at a production state directory.

For manual local use, run `python spike/live-sync/test_browser.py --serve`, open the printed loopback URL in two browsers, bootstrap family A once, copy its second fake grant into the other browser, and connect both. Click Gift and observe both wallet values. Stop with Ctrl-C. Restarting creates empty synthetic state. The controls are intentionally not a real login flow.

## Verified behavior and boundaries

The Playwright run uses three independent Chromium browser processes: two for family A and one for B. It checks actual wallet values and transaction history, each supported mutation's concrete result and notification, false and zero no-op results, replay and conflict, same-family push, no cross-family push, rejected cross-family socket/read, concurrent distinct writes and exact one notification per socket for same-ID retries, disconnection/reconnect snapshot, revoked read/socket and subsequent push denial, and forced expiry including new socket rejection and no subsequent pushes. It also checks the bank's special zero-gain matured bond: collection returns zero but changes state, so it emits once; the fixture compares bank rows for zero-result collections. It injects a failure after the authorization operation insert and checks rollback, no notification and successful retry. One page switches A to B while holding an old A response; it verifies socket closure, ignores the old response and a captured stale handler, sees no refresh or invalidation when A changes, keeps B functional, and closes on logout. Negative push checks use a bounded observation window. Existing hosted integration has broader full-database snapshot coverage.

Each mutation matrix event is checked for the exact invalidation payload and followed by a 400 ms quiet period, then its replay has a separate 400 ms quiet period before the next action. Cross-family isolation is observed in both directions with bounded windows (normally 400 ms; some other negative checks use 300 ms). These windows detect locally delayed events only; they cannot prove indefinite absence. Controlled delayed HTTP completions and captured lifecycle callbacks test switching and logout, alongside a real held snapshot and queued message. The delayed HTTP responses and WebSocket lifecycle interleavings are test controls, not evidence of network cancellation. Ignoring a stale mutation response does **not** undo or prove cancellation of a server commit; setup may likewise already have executed. Logout clears this fixture's credential fields and closes its socket, but is not real credential revocation.

An active socket close or error clears the displayed balance and reports disconnected, invalidating in-flight snapshots without claiming why the connection dropped. It retains fixture credential fields for manual retry; logout and account-context changes clear them. The browser test covers actual revocation closure and a separate transport close, plus simulated error and stale callbacks. It checks exactly one initial gift event on each authorized socket after a bounded quiet interval. There is no automatic reconnect.

This is **not production ready**: the JS gateway and fake identities are intentionally unauthenticated, grants are visible in the page/URL, session ownership is not tied to real browser identity, WebSockets keep the DO resident, and no scale, hibernation, eviction, multi-region or deployment behavior is tested. Expiry is forced by a synthetic DB edit; idle sockets are closed upon a later authorization sweep, not by a timer. There is no durable event/outbox or revision: a crash after commit and before push can lose an invalidation. Manual reconnect and visible-tab resume fetch a fresh authorized snapshot, but there is no automatic reconnect or periodic reconciliation for a continuously connected client. The fixture discards older in-flight refreshes, but has no server revision to order snapshots. Real credentials, a trusted gateway, access revocation across devices, hardened origin/session handling, durable revisions/reconciliation, lifecycle management and production security review remain future work. This spike proves local integration only, not a hosted service or production authorization.
