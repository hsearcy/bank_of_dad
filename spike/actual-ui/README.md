# Actual UI local read-only synthetic fixture — NEVER DEPLOY

This is a disposable local experiment, not a hosted application, an authentication system, or a production security boundary. **Never deploy it or use real identities, money or data.** It binds loopback only and uses temporary Wrangler source, HOME/cache and persistent state. The browser sees the actual application template, CSS and JS; the harness injects only the synthetic session script. The fake identities and grants are not evidence of real authentication.

The loopback client understands revision-bearing invalidations. This remains a synthetic read-only experiment, not a production integration.

## Separation and scope

- `dashboard-proxy.cjs` is the loopback dashboard ingress. It rejects every non-GET request, including gift, save, spend, other existing mutation routes and unknown paths, and never forwards test control paths. It forwards only the WebSocket upgrade for the fixture socket. The internal worker independently rejects non-GET dashboard requests, including asset and root POSTs.
- `caller.js` runs on a **separate internal loopback port**. Only the test harness talks directly to its `/__test/setup` and `/__test/mutate` controls, using a fresh per-run secret supplied in disposable Wrangler configuration and the test process environment. Bootstrap creates fake principals and initial synthetic data; mutations call the real Python bank through the synthetic test driver, not through the dashboard gateway. These privileged controls and their secret are test machinery, not a production access design. A local user able to inspect the harness or temporary config can obtain the secret. Separate loopback ports are not a security boundary: local processes and potentially browser-origin requests can reach loopback; the driver does not enforce a trustworthy Origin or protect secrets from an untrusted local environment. Never expose either port to untrusted users. Manual `--serve` does not bootstrap the dashboard; bootstrap is intentionally in the isolated automated driver, not a dashboard control.
- The synthetic browser script hides and disables Dad, spend, save, invest and reward-collection controls; mutator entry points also return before local optimistic effects and the client rejects API mutations. It contains no pending-operation or recovery UI. The gateway, not CSS or JavaScript, is the read-only enforcement point. Existing non-fixture application behavior is unchanged.
- `bank_worker.py` retains the real `FamilyAuthorization`, `FamilyService`, SQLite adapter, bank domain methods and ordinary Python Durable Object WebSocket. Snapshot and transaction reads are authorized within the family. Successful new driver mutations broadcast revision-bearing invalidations only to sockets whose grants still authorize. This is synthetic state, not a second ledger.
- Synthetic mode suppresses the service worker and ordinary 30-second poll. Revision-bearing invalidations refetch on increases; a 60-second safety read recovers lost notifications and detects expired grants (tests accelerate it). Open and visible resume also refresh. Higher durable revisions win even from earlier-started requests; equal revisions apply in settled-request order, preserving time-derived updates without waiting indefinitely for newer in-flight requests. Lower revisions and stale view generations cannot roll back the dashboard. Socket loss clears the display and schedules exponential reconnect, capped at 30 seconds; each preflight aborts after five seconds and transient failures retry. Offline pauses retries; hidden tabs may be browser-throttled and a visible resume requests reconciliation. Logout, family switch and denied reads stop timers and clear credentials. Session epochs, request ordering and socket identity fence stale completions. The fake token is present in the WebSocket URL and may appear in tools or logs.

## Run

From the repository root, with Node.js supported by the pinned Wrangler and local Chromium:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
(cd tests_hosted && npm ci --ignore-scripts)
export PLAYWRIGHT_MODULE="$PWD/tests_hosted/node_modules/playwright"
# Optional: export CHROMIUM=/path/to/chromium
.venv/bin/python spike/actual-ui/test_browser.py
.venv/bin/python spike/actual-ui/test_normal_browser.py
```

`WRANGLER_BIN` can override the pinned local binary and `TMPDIR` the disposable parent directory. The harness stops its owned dashboard proxy and Wrangler process group, closes the two browser processes, removes temporary source and state, and checks that its forbidden self-host DB was not created. `--serve` exposes only the read-only dashboard for manual inspection until Ctrl-C; it does not issue grants or populate data.

## Verification

`browser.cjs` launches **two independent Chromium processes**. With ordinary dashboard polling disabled and the 60-second safety interval unaccelerated for push checks, it uses the private test driver to seed two fake families and make real gift/save/spend mutations; both actual dashboards update through revision-bearing invalidations. A separate accelerated safety test suppresses notification after a real commit and verifies recovery without a frame. It holds a real old-revision snapshot across a later commit, injects duplicate/lower frames and a lower-revision response, advances the synthetic read clock to test equal-revision interest, forces socket loss and automatic reconnect, simulates offline/online, and checks real grant revocation and expiry. It verifies cross-family read, driver-mutation and socket denial, no cross-family push, visibility resume after deliberately dropping push, old family callbacks and held state/history across switch/logout. It verifies hidden money controls, exercises visible what-if/graph/history interactions, rejects dashboard POSTs for supported and unsupported paths, and compares deterministic full snapshots of both families before and after all dashboard POST attempts, including every SQLite table, schema catalog and sequence. Driver controls are rejected on the dashboard ingress and without the secret on the internal port. The real Flask app is separately tested to confirm fake control routes are absent.

The authorized driver gift is a positive control: the full snapshot, child row, ledger and SQLite sequence change while the other family's snapshot and the schema remain unchanged. Schema is included but deliberate schema-change sensitivity is not exercised. All three reward handlers, every rendered fast-forward button and the static Dad and money entry points are invoked directly; no browser write request, optimistic DOM/state change or server snapshot change is allowed. Dynamic Dad gift, allowance, edit-history and rates handlers cannot be independently invoked in synthetic mode because their guarded renderers never create them; the test verifies those elements remain absent, rather than bypassing or rewriting the guard. Dynamic edit/delete transaction and money-modal submission handlers are likewise unreachable through guarded entry points. This is not exhaustive proof against arbitrary injected scripts.

`test_normal_browser.py` starts the real Flask app on an ephemeral loopback port with a fresh temporary database. With no fixture injection, Chromium performs first-run PIN setup and re-entry, adds a child, gifts and saves money, verifies service-worker activation, and checks the registered 30-second poll callback by invoking it directly (not by waiting 30 seconds). Both the Flask server and its database are discarded. The synthetic test also covers an older success overtaken by a newer injected failure and an old-family injected failure delivered after switching families. These browser-intercepted 500s model failures, not actual outages. The suite holds a higher-revision real response out of request order, an old denial across a later 500, and a history response across reconnect; it checks that old-context denials cannot clear a replacement session. The hanging preflight test uses the real five-second timeout; the backoff-cap test compresses only retry timers by 100× and asserts the original delay sequence and logout cancellation. Family-switch cancellation uses real timing. An injected unsupported driver action exercises the actual gateway generic 500; it is not a real infrastructure outage.

## Limitations

WebSocket invalidation is non-durable; the safety read gives eventual recovery while the page is running, but background timer throttling, network loss and outages can delay it. Expiry is detected on the next authorized read, not exactly at its deadline. The synthetic clock control changes read-time calculation only, without changing durable domain rows or authorization time. Suppressing notification models a post-commit loss, not a process crash. There is no outbox, production identity, real browser auth, hibernation, eviction, scaling, deployment or live-data verification. Local logout does not revoke a fake grant.

A future money-enabled dashboard must first implement and validate **authoritative server-side operation recovery** for uncertain outcomes and duplicate human intent across lost browser state, tab/device changes, logout and account switching. Replaying a client-generated operation ID while it survives in session storage is not sufficient. This fixture deliberately avoids dashboard writes rather than claiming to solve that problem.
